# Decisions 1 to 16

The full records; [the index](../decisions.md) lists every decision in one line.

1. **Profile `prototype`; euginevd owns the code and accepts every trade-off in [guides/03-security-trade-offs.md](../../guides/03-security-trade-offs.md)** (2026-11-13). `dev` only, 50% coverage, and trading is bounded by decision 8. Why: one owner, no customers, and only the owner's own money. Instead of: `production`, which needs a second reviewer and a second AWS account.
2. **The agent never reads an exchange key, and the `.env` deny rules stay in `.claude/settings.json`** (2026-11-13). The owner puts each key in `.env` (Binance, Anthropic, Taostats); the agent troubleshoots from logs. Why: a prototype's secrets are meant to be made up, and these guard real money. Instead of: AGENTS.md rule 13's default, which drops the deny rules, and rule 26's leave to read `.env`.
3. *Superseded by 14:* deploy to Lambda, HTTP API, DynamoDB, Secrets Manager, Cognito, S3 and CloudFront in `ap-southeast-2`.
4. **One web app, `desk`, with a dashboard that links to each product's screens** (2026-11-13). Why: one user and one sign-in. Instead of: an app per audience, as in travel-claims.
5. **The repo is public, as every personal or portfolio project is, so nothing secret goes in code, Terraform or its state** (2026-11-13). Why: it's built in the open (AGENTS.md rule 30), and anyone signed in to GitHub can download `main`'s saved plan for a day (trade-offs 5). Account IDs and resource names are accepted as visible. Instead of: a private repo, kept for work projects.
6. **Personal use for three months, then a decision on commercialising** (2026-11-13). Why: prove it on the owner's own account first; trading for others brings licensing (spec, Business). Instead of: building for other users from the start.
7. *Superseded by 14:* local first, then AWS.
8. **The MVP is a dashboard and spot trade terminal; the Binance key reads and trades spot only** (2026-11-13). No withdrawal, margin or futures, and limited to the IP address it calls from. Testing is on the live account, within the owner's limits (decision 12). Why: the owner wants to trade from the desk from the start. Instead of: a read-only MVP, with manual trades as the next stage.
9. **Portfolio page: spot wallet only, valued in US dollars with an Australian dollar total, profit or loss by average cost** (2026-11-13). Prices are each coin's USDT pair, with USDT, USDC and FDUSD at $1. Average cost comes from the coin's trades against those three; coins deposited, or bought through another pair, show what the trades cover and say so. Fetched on opening the page and on Refresh, not stored; Binance calls run side by side, and each coin's trade history is kept in memory until its balance changes (2026-11-14: Refresh went from 15 s to under half a second). Why: the owner's answers to TODO 1; average cost is the simplest method that's still honest. Instead of: Funding and Earn wallets, first-in first-out cost, or stored snapshots.
10. **Locally, the `api` listens on `127.0.0.1` only and needs no sign-in** (2026-11-13). Sign-in comes with hosting (spec 9, decision 14). Why: one owner on their own machine, and nothing else can reach it. Instead of: a sign-in stand-in from the first feature.
11. *Superseded by 15:* the house tokens, following the system's light or dark.
12. **Smart trade, first version: a market or limit buy with one take-profit and one stop-loss, on the live account** (2026-11-14). The exits go to Binance as one OCO order once the buy fills, so they hold while the desk is off; a limit buy that fills while the desk is off gets its exits when the desk next runs, and the page says so. Tested live within the owner's per-order and daily limits, zero until the owner sets them. Why: the owner's answers to TODO 2. Instead of: several targets, trailing or breakeven stops, or the testnet first.
13. **Locally, smart trades, limits and the kill switch are kept in a SQLite file in `local/`** (2026-11-14). Why: Python has it built in, and it survives a restart. Instead of: a DynamoDB stand-in before AWS. In Docker, `local/` is mounted into the `api` container, so the file stays on the owner's disk (decision 14).
14. **Runs locally in Docker; hosting is decided later. The AWS app (`infra/aws/api`) is removed; the `aws` workflow and the bootstrap stay, idle until a unit comes back** (2026-11-14). `docker compose up` starts `api` and `desk`, published on `127.0.0.1` only. Why: the owner's brief (TODO 3) asks for a local Docker prototype, and an unused Lambda, Cognito and pipeline would only drift. Instead of: local first, then AWS (old decision 7) and the Lambda deploy target (old decision 3). With no unit in `infra/aws/`, every job in the `aws` workflow skips; it stays because `scripts/setup.sh` and the Terraform checks read its version. What it throws away: the Lambda's Terraform, which git keeps; when hosting comes back, it starts from a fresh spike, and a container host is now the likelier fit (a fixed address for Binance's allowlist, and the trade watcher running all the time).
15. **Theme: dark only, after the owner's mockup: near-black panels, a teal accent, green and red for up and down, Inter with tabular figures** (2026-11-14). Why: the owner's brief takes its look and layout from Hyperliquid and supplies the mockup (TODO 3). Instead of: the house light and dark tokens (old decision 11).
16. **AI signal: Claude Opus 5.5 (`claude-opus-5-5`) through the Anthropic API, advisory only** (2026-11-14). For each watchlist coin it reads the price, indicators worked out in code from Binance candles (RSI 14, 20 and 50 period averages, support and resistance), and news found with Claude's web search, and returns Buy now, Wait or Avoid, a confidence from 0 to 100%, a one-line summary and three reasons, as a fixed JSON shape checked in code. It runs when a coin is added and on Re-run, and each answer is kept until it's re-run or 4 hours old. It never sees balances, keys or orders and can't place an order: the owner places every order from the order form, inside the limits and kill switch (spec 10). A monthly cap on Anthropic spend, $20 until the owner changes it, is checked in code. Why: the owner chose Claude for the signal. Instead of: a rules-only signal with no model, or an agent that trades.
