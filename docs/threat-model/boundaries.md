# Trust boundaries in full

The detail behind [threat-model.md](../threat-model.md)'s trust boundaries and its data flow.

- **TB1** Browser to `api`: both containers publish on `127.0.0.1` only, so only the owner's machine reaches them. There's no sign-in (decision 10), so any process or web page on the machine is a possible caller: the `api` allows only the desk's origin and checks `Content-Type` on every write.
- **TB2** `api` to Binance and Frankfurter: over TLS; Binance calls are signed. What comes back is untrusted, parsed against a fixed shape and shown as text.
- **TB3** `api` to Taostats: over TLS, sending only the public address.
- **Binance deposit history** (decision 31): the api reads the USDC deposit history with the same read-only key, and keeps what the owner paid per deposit in the local SQLite under `local/`, git-ignored. The owner's figures never go in tests, demo data or docs ([known-mistakes 7](../known-mistakes.md)).
- **Fear & Greed Index** (decision 36): the api asks `api.alternative.me` for the index, with no account data, at most every 10 minutes, and checks the value is 0 to 100.
- **Fear & Greed details and market size** (decision 42): the api asks `api.alternative.me` for a year of the index and CoinGecko's `/global` for the market's size, volume and dominance (also for the header, decision 44), with no account data, kept 10 minutes; what comes back is checked and shown as numbers and fixed words.
- **TB4** `api` to Anthropic, by API key or the owner's subscription through Claude Code, whose process may only search the web and gets no other secret (decision 48): sends a coin's computed figures and the owner's position in it (amount, average cost, PnL, share, cash, the portfolio's total value, open orders' side, price and amount: decision 46), never keys, account ids or order ids. What comes back, including text from web pages it searched, is untrusted: checked against a fixed shape and shown as text.
- **TB5** `api` to CoinGecko: sends a coin's ticker once to find its logo, so CoinGecko can see which coins the desk shows, never amounts. Logos are taken only from CoinGecko's image host, only as PNG, JPEG or WebP (never SVG), up to 256 KB, and kept in `local/icons/`. Each portfolio refresh also asks CoinGecko for USDT's price in AUD and INR (decisions 29, 30): no account data is sent, and a reply outside 0.8 to 3 is ignored for the ECB's rate.
- **TB6** `api` to Telegram: the bot token goes only in the request URL and is never logged; it sends the morning summary, risk alerts and the agents' proposals, never keys, only to the chat linked by a one-time code (decision 57, known-mistakes 29c). Inbound, it reads only button taps: each carries a random token kept with its action and expiry, taken once, and counted only when both the chat and the tapper are the owner's linked chat; the tap then runs the same code as the desk's button, so every check applies again (decision 74).
- **TB7** Freqtrade containers (apps/backtest, third-party image, no keys) to `api`: by the service name `api:8000` (DESK_HOSTS), which the api accepts for `POST /pot/judge-one` only and never with a browser Origin; that route asks trading-agent and sizes or places nothing (decision 84). Every other route refuses that name.
- **TB7, the other way** (decision 85): the api queues a Backtest page run as a file in `local/backtest/jobs`, never by starting a process or through the Docker socket. The `backtest-worker` re-checks it (a fixed style, a flag and two dates, `api/backtest_runs.py`) and runs Freqtrade from an argument list, never a shell; anything else is marked failed. The api opens results only by an id matching Freqtrade's own file names. The worker has no port, no keys and no database; it downloads Binance's public candles.
